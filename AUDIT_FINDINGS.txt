[x] F1 — TLS-Branch Code-Duplizierung → Auth-Bypass-Risiko
----------------------------------------------------------------------
  Modul:      phantom-node
  Datei:      crates/phantom-node/src/main.rs
  Zeilen:     (HTTP+TLS-Endpoint-Setup, ~Z.800-2500)
  Confidence: high

  Risiko:
    Die HTTP-Endpoints werden zweimal definiert: einmal fuer Plain-HTTP,
    einmal fuer TLS. Aenderungen an Auth-Guards in einem Branch werden
    leicht im anderen vergessen → Auth-Bypass auf TLS oder umgekehrt.

  Fix:
    Endpoints in eine gemeinsame Funktion extrahieren, die sowohl fuer
    Plain als auch TLS verwendet wird. Nur die Transport-Schicht (TLS
    vs. Plain) unterscheiden, nicht die Handler.

  Test:
    Automatisierter Test der prueft, dass alle Endpoints in beiden
    Branches identische Auth-Guards haben.

[x] F38 — HSM Vote-Domain weicht von main.rs ab → ungueltige Signaturen
----------------------------------------------------------------------
  Modul:      pkcs11_sign
  Datei:      crates/phantom-signer/src/pkcs11_sign.rs
  Zeilen:     Z.122-132 (seat_vote_sign_with_hsm)
  Confidence: high

  Risiko:
    Die Vote-Message in pkcs11_sign.rs verwendet:
      Domain: b"SV"
      round:  u16 (2 bytes)
    Waehrend main.rs (Z.3287-3294) verwendet:
      Domain: b"pc:vote:seat:v1\x01"
      round:  u64 (8 bytes)
    Die Messages sind komplett verschieden — eine HSM-Signatur wird von
    keinem Verifier akzeptiert.

  Fix:
    SeatVote PKCS#11 HSM-Signing fail-closed deaktivieren, bis ein
    PKCS#11-Mechanismus fuer die protokoll-erforderlichen Schnorr-
    Signaturen verfuegbar ist. Der bisherige PKCS#11 ECDSA-Mechanismus
    kann keine gueltigen SeatVote-Signaturen erzeugen; eine "falsche"
    Signatur darf nie im System entstehen (Consensus-Safety).

  Test:
    Unit-Test: seat_vote_sign_with_hsm muss fail-closed abbrechen und
    darf keine Signatur liefern.

----------------------------------------------------------------------
  Modul:      phantom-node
  Datei:      crates/phantom-node/src/main.rs
  Zeilen:     (~Z.5700-5750, journal_append)

    naechsten Start korrekt geladen werden (ohne den korrupten
    Eintrag).

----------------------------------------------------------------------
