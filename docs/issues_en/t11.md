Context:
- This issue specifies the first anchor (A0, “genesis”) for PhantomCoin, the canonical network identifier, and the commitment mechanics for `genesis_note`.
- It defines bootstrapping exceptions for `k=1` and formalizes rules for empty anchors so that all nodes derive the same initial state deterministically.

Goals:
- Define the exact data model and encoding for `genesis_note` and the resulting commitment used to derive the network seed/network ID.
- Specify k=1 bootstrap behavior to allow the network to start deterministically before normal committee election rules take over.
- Specify what constitutes an empty anchor and how nodes handle it (validation, hashing, storage, and gossip constraints).

Non‑Goals:
- Consensus after genesis (rotation, attestations, slashing) – covered by separate issues (t12–t14).
- Wallet/payout policy – out of scope here.

Definitions:
- Anchor (A_i): An epoch boundary item with header+payload. A0 is the first anchor.
- `genesis_note`: Canonical data record embedded in A0 payload with minimal fields sufficient to bind the network identity and initial parameters.
- Network ID: 32‑byte identifier derived from `genesis_note` commitment; used across P2P, encoding domains, and config.

Data Model (genesis_note):
- Fields (canonical order):
  1. `version: u8` (must be 0x00 for A0 v1)
  2. `network_name: string` (UTF‑8, <= 32 bytes; examples: "phantom-dev", "phantom-testnet-1")
  3. `seed: [u8; 32]` (deterministic seed, e.g., Blake3("phantom:", network_name))
  4. `params: GenesisParams` (see below)
- `GenesisParams`:
  - `shards_initial: u16` (default 64)
  - `committee_k: u8` (default 21; upper bound 64)
  - `txs_per_payload: u16` (default 256)
  - `features: u64` (bitflags; default 0)

Commitment and Network ID:
- Encode `genesis_note` with the canonical codec (`pc-codec`, fixed‑length/varints, domain separation tag `GENESIS_NOTE_V1`).
- Compute `commit = blake3( domain_tag || encode(genesis_note) )` (32 bytes).
- Set `network_id = commit`.
- Store `network_id` in node config and expose via status/metrics.

Anchor A0 Structure:
- Header (A0):
  - `parent: None` (no previous anchor)
  - `height: 0`
  - `payload_root = merkle_root([encode(genesis_note)])`
  - `network_id = commit` (redundant field to bind header to genesis)
- Payload (A0):
  - Single entry: `genesis_note`.

Validation Rules (A0):
1) `height == 0` and `parent == None`.
2) `payload` must contain exactly one item: a `genesis_note` (version 0x00).
3) Recompute `commit` from the decoded `genesis_note` and assert `payload_root == merkle_root([encode(genesis_note)])`.
4) Assert `header.network_id == commit`.
5) Verify `GenesisParams` constraints:
   - `1 <= committee_k <= 64` (and must equal configured `RECOMMENDED_K` for the target network profile unless explicitly overridden)
   - `shards_initial >= 1` (recommended 64)
   - `txs_per_payload >= 1` (recommended 256)

Bootstrap Exceptions (k=1):
- Purpose: Allow a single validator seat during network bring‑up (no rotation/VRF yet).
- Rules:
  - While `height == 0` and until the first successful rotation epoch completes, the effective committee size MAY be treated as `k=1` (bootstrap seat).
  - Gossip/REQ‑RESP must accept A0 with `k=1` semantics without triggering anti‑entropy or slashing logic.
  - As soon as rotation is activated (per t12), nodes must enforce `committee_k == params.committee_k`.
  - Any votes/attestations emitted under k=1 MUST be marked as `bootstrap=true` to prevent misinterpretation in later epochs.

Rules for Empty Anchors:
- Definition: An anchor is "empty" if its payload would be empty under normal processing (no txs/mints/claims). For A0, payload is never empty because it contains `genesis_note`.
- For A_i (i>0), empty anchors are permitted only if:
  - `payload_root == merkle_root([])` where `[]` encodes as the canonical empty list under `pc-codec`.
  - Header must still be fully valid (height increment, parent linkage, signatures/attestations).
  - Empty anchors MUST NOT be used to bypass DA gating rules (see t14): votes without local data are invalid.

Encoding and Domain Separation:
- Use `pc-codec` canonical rules (fixed lengths, varints). Define a dedicated domain tag `GENESIS_NOTE_V1` in `pc-types`.
- All hashes use Blake3 with typed domain tags (`digest_*` helpers in `pc-types`).

Storage and Exposure:
- Persist `genesis_note` and `network_id` under `store_dir` at first boot; on restart, verify they match configured network profile.
- Expose `GET /status` fields: `network_id`, `genesis_height=0`, `genesis_params`.
- Metrics: `pc_network_id{network="<name>"} 1`, `pc_genesis_height 0`.

Security Considerations:
- Mismatch between local config and `genesis_note` must abort startup.
- Network split risk: differing `genesis_note` across nodes → prevent by pinning `network_id` in configs and distributing signed genesis bundle.
- k=1 window must be strictly bounded to bootstrap only and clearly signaled.

  - A0 header validation (parent=None, height=0, payload_root matches, network_id matches).
- Integration tests:
  - Node boots with A0, exposes `network_id` via status.
  - Mismatch config vs. stored `network_id` → startup error.
  - Empty anchor A1 allowed only with correct empty payload root; DA gating enforced.
