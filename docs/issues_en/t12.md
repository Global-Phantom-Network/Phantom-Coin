## VRF Committee Selection Algorithm

### Seed Derivation
```
seed = BLAKE3("pc:vrf:seed:v1\x01" || network_id(32) || last_anchor_id(32))
```
- Deterministically derived from network state
- Changes per anchor (new last_anchor_id)
- 32-byte output used as VRF input seed

### Epoch Calculation
```
epoch = floor(current_anchor_index / epoch_len)
```
- epoch_len is clamped to minimum 1
- Multiple anchors share the same epoch
- Epoch changes trigger potential rotation

### VRF Message Format
```
vrf_message = "pc:vrf:committee:v1\x01" || seed(32) || epoch(8, little-endian)
```
- Domain-separated to prevent cross-protocol attacks
- Includes seed for anchor-specific uniqueness
- Includes epoch for time-based rotation

### Score Calculation
```
score = VRF_output = BLS_VRF_verify(vrf_message, vrf_proof, bls_pk)
```
- VRF output is a 32-byte hash
- Lower hash values = better scores (lexicographic sort ascending)
- Deterministic: same inputs always produce same outputs

### Selection Process
```
1. For each candidate:
   a. Check eligibility:
      - stake >= MIN_ATTESTOR_STAKE (M3-Fix: minimum stake requirement)
      - attendance_recent_pct >= params.min_attendance_pct
      - (current_anchor_index - last_selected_at) >= params.cooldown_anchors
   b. Verify VRF proof: BLS_VRF_verify(vrf_message, vrf_proof, bls_pk)
   c. Extract score (VRF output hash)

2. Sort candidates by score (ascending, lexicographic)

3. Greedy anti-collocation selection:
   - Iterate sorted candidates
   - Skip if operator_id already used
   - Add to selection, mark operator_id as used
   - Stop when k seats filled or candidates exhausted

4. Return selected seats
```

## Anti-Collocation Mechanism

**Goal:** Prevent single operators from controlling multiple committee seats.

**Algorithm:**
- Use `operator_id` as unique operator identifier
- Maintain HashSet of used `operator_id` during selection
- Skip candidates with already-used `operator_id`
- Guarantee: At most one seat per `operator_id` in final committee

**Rationale:**
- Enhances decentralization
- Prevents Sybil attacks at operator level
- Balances power across distinct entities

## Eligibility Rules

### Attendance Threshold
```rust
if candidate.attendance_recent_pct < params.min_attendance_pct {
    reject_candidate();
}
```
- `attendance_recent_pct`: Percentage of recent rounds where candidate signed
- Typical value: 50-80%
- Prevents selection of unreliable validators
- Incentivizes high uptime

### Cooldown Period
```rust
if (current_anchor_index - candidate.last_selected_at) < params.cooldown_anchors {
    reject_candidate();
}
```
- `cooldown_anchors`: Minimum anchors between consecutive selections
- Typical value: 5,000-10,000 anchors
- Prevents rapid re-selection of same validators
- Distributes opportunities across candidates
- Uses saturating subtraction to handle genesis case

### VRF Proof Validity
```rust
if !BLS_VRF_verify(vrf_message, candidate.vrf_proof, candidate.bls_pk) {
    reject_candidate();
}
```
- Cryptographic proof that candidate participated in VRF protocol
- Tampered or incorrect proofs are rejected
- Ensures only legitimate candidates are considered

## Fairness Mechanisms (Attestor Fair Sampling)

### Cap Enforcement
```rust
let count = recent_op_selection_count.get(&candidate.operator_id).unwrap_or(&0);
if *count >= cap_limit_per_op {
    reject_candidate();
}
```
- Hard cap on recent selections per operator
- Prevents single operator from dominating attestor pool
- Enforced before VRF score comparison

### Performance Index Tiebreaker
```rust
// Sort order: VRF score ASC → Performance DESC → recipient_id ASC
scored.sort_by(|(score_a, perf_a, cand_a), (score_b, perf_b, cand_b)| {
    match score_a.cmp(score_b) {
        Equal => match perf_b.cmp(perf_a) {  // DESC: higher perf is better
            Equal => cand_a.recipient_id.cmp(&cand_b.recipient_id),
            other => other,
        },
        other => other,
    }
});
```
- VRF score is primary determinant (randomness)
- Performance index breaks ties (quality)
- recipient_id breaks final ties (determinism)

### Multi-Criteria Optimization
- **Randomness:** VRF ensures unpredictability
- **Quality:** Performance index rewards reliable operators
- **Fairness:** Caps prevent centralization
- **Determinism:** Tiebreakers ensure reproducibility

## Security Considerations

### VRF Uniqueness
- Each (seed, epoch, bls_pk) tuple produces unique VRF output
- Impossible to predict output without secret key
- Prevents pre-computation attacks

### Cooldown Protection
- Prevents rapid re-selection exploitation
- Ensures diverse validator set over time
- Mitigates single-point-of-failure risk

### Attendance Incentives
- Low attendance = exclusion from future selections
- Incentivizes high uptime and reliability
- Self-healing: unreliable validators naturally excluded

### Cap Limits
- Hard caps prevent operator dominance
- Even with many Sybil identities, limited to cap_limit_per_op selections
- Promotes decentralization at operator level

### Anti-Collocation
- One seat per operator_id in committee
- Prevents single entity from controlling multiple votes
- Critical for consensus safety (>2/3 threshold attacks)

### Minimum Stake Requirement (M3-Fix)
- `MIN_ATTESTOR_STAKE = 10_000 * COIN` (10,000 PC)
- Candidates with stake < MIN_ATTESTOR_STAKE are rejected
- Prevents Sybil attacks with minimal capital investment
- Ensures attestors have "skin in the game"
- Stake must be provided by caller (from state/staking contract)

## Performance Characteristics

### Computational Complexity
- Eligibility filtering: O(n) where n = candidate count
- VRF verification per candidate: ~1-2ms (BLS pairing)
- Sorting: O(n log n)
- Anti-collocation selection: O(k) where k = committee size
- **Total:** O(n log n) + O(n × VRF_cost)

### Scalability Limits
- Recommended max candidates: 10,000
- Committee size k: 1-64 (typical: 21)
- Attestor pool m: 1-256 (typical: 64)
- VRF verification parallelizable

### Optimization Strategies
- Cache VRF verifications within same epoch
- Pre-filter obviously ineligible candidates
- Use parallel verification for large candidate pools
- Index operator_id for fast collocation checks

## Troubleshooting Guide

### Empty Committee Selected
**Symptoms:** `committee_select_vrf()` returns empty Vec
**Causes:**
1. All candidates in cooldown → Reduce `cooldown_anchors`
2. All candidates below attendance threshold → Reduce `min_attendance_pct`
3. All VRF proofs invalid → Check candidate proof generation
4. k=0 or candidates empty → Check input parameters

### Non-Deterministic Selection
**Symptoms:** Same inputs produce different committees
**Causes:**
1. Floating-point arithmetic (❌ not used in our impl)
2. HashMap iteration order (✅ we use sorted Vec)
3. Platform-dependent VRF output (check golden tests)
4. Race conditions in state management

### Operator Centralization
**Symptoms:** Same operators selected repeatedly
**Causes:**
1. Insufficient candidate diversity
2. Cooldown too short
3. VRF bias (should be investigated if observed)
4. Caps not enforced (check fair sampling)

## Migration Path

If upgrading from non-VRF committee selection:
1. Deploy VRF-capable nodes (backward compatible)
2. Accumulate VRF proofs from validators
3. Switch from old to new selection at epoch boundary
4. Monitor metrics for anomalies
5. Keep rollback capability for N epochs
