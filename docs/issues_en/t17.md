# T17: Testing Strategy

## Overview

This document specifies the comprehensive testing strategy for Phantom Coin. The testing infrastructure ensures correctness, security, and reliability through multiple layers of validation including property-based testing, fuzzing, consensus validation, network simulation, and continuous integration gates.

## Goals

1. **Correctness**: Verify functional correctness of all core components
2. **Security**: Detect Byzantine attacks, double-spends, and equivocation
3. **Resilience**: Validate behavior under adverse network conditions
4. **Regression Prevention**: Automated gates to prevent quality degradation
5. **Coverage**: Achieve >70% test coverage across critical paths

## Implementation

### 1. Property-Based Testing

**Location**: `crates/*/src/lib.rs` (embedded with `proptest!` macro)

**Coverage**:
- **pc-types**: Codec roundtrip properties (MicroTx, AnchorHeader, etc.)
- **pc-state**: UTXO state transitions, balance conservation, double-spend rejection
- **pc-consensus**: Slashing distribution, equivocation penalties
- **pc-codec**: Varint encoding, vector serialization

**Configuration**:
```rust
proptest! {
    #![proptest_config(ProptestConfig::with_cases(1000))]
    
    #[test]
    fn prop_balance_conserved_on_apply(...) {
        // Property: Total amount in = Total amount out
    }
}
```

**Key Properties Tested**:
1. **Codec Roundtrip**: `encode(decode(x)) == x`
2. **Balance Conservation**: `sum(inputs) == sum(outputs) + fee`
3. **Double-Spend Rejection**: Second spend of same UTXO fails
4. **Slashing Distribution**: `sum(payouts) == slashed_amount`
5. **Equivocation Penalty**: Always 100% slash

**CI Integration**: `.github/workflows/proptest-gate.yml`

### 2. Fuzz Testing

**Targets**:

#### UTXO State Fuzzing (`crates/pc-state/fuzz/`)
- `utxo_apply_mint.rs`: Random mint events with 1-10 outputs
- `utxo_apply_microtx.rs`: MicroTx application with edge cases
- `utxo_state_snapshot.rs`: Snapshot/restore roundtrip
- `utxo_merkle_root.rs`: Merkle root determinism

#### Crypto Fuzzing (`crates/pc-crypto/fuzz/`)
- `merkle_root_varying_leaves.rs`: Merkle tree with 0-100 leaves
- `merkle_proof_verify.rs`: Proof generation/verification
- `blake3_hash.rs`: Hash function determinism

#### Codec Fuzzing (`crates/pc-codec/fuzz/`)
- `codec_varint.rs`: Variable-length integer encoding
- `codec_vec.rs`: Vector serialization

**Running Fuzz Tests**:
```bash
# Install cargo-fuzz
cargo install cargo-fuzz

# Run UTXO fuzz tests
cd crates/pc-state
cargo fuzz run utxo_apply_mint -- -max_total_time=300

# Run crypto fuzz tests
cd crates/pc-crypto
cargo fuzz run merkle_root_varying_leaves -- -max_total_time=300
```

**CI Integration**: `.github/workflows/fuzz.yml`

### 3. Consensus Tests

**Byzantine Attack Detection** (`crates/pc-consensus/tests/byzantine_simple.rs`):

1. **Double-Vote Detection**: Equivocation always results in 100% slash
2. **Double-Spend Prevention**: UTXO layer rejects spent outputs
3. **Withholding Tolerance**: Not voting is not slashable (by design)

**Fork Resolution** (`crates/pc-consensus/tests/fork_simple.rs`):

1. **Longest Chain Rule**: Higher chain wins fork
2. **Partition Recovery**: Nodes converge after network heal
3. **Stake-Based Tiebreaker**: Equal heights resolved by cumulative stake
4. **Reorg Protection**: Deep reorgs (>100 blocks) rejected
5. **Shallow Reorgs**: Recent reorgs (<100 blocks) accepted

**Slashing Tests** (existing in `crates/pc-consensus/src/lib.rs`):
- Equivocation: 100% slash (10,000 basis points)
- VoteInvalid: 50-100% slash (5,000-10,000 bp)
- ConflictingDAAttest: Configurable slash

### 4. Network Simulation

**Framework**: `crates/pc-netsim`

**Network Conditions**:
```rust
pub enum NetworkCondition {
    Perfect,        // 0% loss, 0ms delay
    Realistic,      // 1% loss, 10-50ms delay
    Poor,           // 5% loss, 50-200ms delay
    Terrible,       // 25% loss, 200-1000ms delay
    Partitioned,    // 100% loss (network split)
}
```

**Test Scenarios** (`crates/pc-netsim/tests/consensus_under_stress.rs`):

1. **Consensus Under 5% Packet Loss**
   - 3 nodes, 100 rounds
   - Expected: >90% success rate

2. **Consensus Under 25% Packet Loss**
   - 3 nodes, 100 rounds
   - Expected: 60-85% success rate

3. **Finality With Network Delay**
   - 200-1000ms delay range
   - Verify finality still achieved

4. **Partition Recovery**
   - Start with 100% packet loss
   - Switch to perfect network
   - Verify all messages succeed

5. **Realistic Network Stress**
   - 5 nodes, 1000 messages
   - 1% packet loss
   - Expected: >95% success rate

**Running Network Simulations**:
```bash
cargo test -p pc-netsim --all-targets
```

**CI Integration**: `.github/workflows/netsim-gate.yml`

## Troubleshooting

### Property Test Failures

```bash
# Reproduce failure with seed
PROPTEST_SEED=1234567890 cargo test prop_balance_conserved

# Get verbose output
cargo test prop_balance_conserved -- --nocapture
```

### Fuzz Test Crashes

```bash
# Minimize crashing input
cd crates/pc-state
cargo fuzz cmin utxo_apply_mint

# Reproduce crash
cargo fuzz run utxo_apply_mint fuzz/artifacts/crash-xyz
```

### Network Simulation Flakiness

Network simulations use randomness. If tests are flaky:
1. Check success rate thresholds (may need adjustment)
2. Increase sample size (more rounds)
3. Use fixed random seed for reproducibility

### Coverage Below Threshold

```bash
# Generate detailed HTML report
cargo llvm-cov --all-features --workspace --html

# View report
open target/llvm-cov/html/index.html

# Identify uncovered lines
cargo llvm-cov --all-features --workspace --show-missing-lines
```
