## A4 – BLS Cross-Protocol Forgery (PoP ≠ normale Signatur)

### Was wurde getestet?
- Proof-of-Possession (PoP) darf **nicht** als normale BLS-Signatur gelten (und umgekehrt).
- Stake/Bond wird abgelehnt, wenn der PoP ungültig ist.

### Tests
- `crates/pc-crypto/src/bls.rs`
  - `bls_pop_cannot_be_used_as_normal_signature_and_vice_versa`
- `crates/pc-state/src/lib.rs`
  - `bond_rejects_invalid_bls_pop`

### Befehle
```bash
cargo test -p pc-crypto bls_pop_cannot_be_used_as_normal_signature_and_vice_versa
cargo test -p pc-state bond_rejects_invalid_bls_pop
```

## A5 – UTXO Dust & State Bloat

### Was wurde getestet?

- Relay-Policy akzeptiert keine Transaktionen, deren Gebühr unter der Mindestgebühr liegt (auch nicht bei `fee == 0`).

### Tests

## A6 – VRF Grinding

### Was wurde getestet?
- Ein zweiter VRF-Key-Wechsel wird abgelehnt, solange ein Wechsel noch „pending“ ist.
- VRF-Key-Rotation zu früh wird abgelehnt (Sperrfrist).

### Tests
- `crates/pc-state/src/lib.rs`
  - `vrf_key_registration_sets_pending_delay_and_blocks_second_change_while_pending`
  - `vrf_key_rotation_too_soon_is_rejected`

### Befehle

```bash
cargo test -p pc-state vrf_key_registration_sets_pending_delay_and_blocks_second_change_while_pending
cargo test -p pc-state vrf_key_rotation_too_soon_is_rejected
```

## A7 – Mempool DoS über unreife MicroTx

### Was wurde getestet?
- Eine unreife MicroTx wird beim Eingang sofort abgewiesen (sie wird nicht in den Mempool aufgenommen).
- Flooding durch einen Absender wird begrenzt (mindestens einmal kommt `429 rate limited`).

### Tests
- `crates/phantom-node/tests/mempool_dos_unripe_microtx_a7.rs`
  - `a7_unripe_microtx_is_rejected_on_admission`
  - `a7_rate_limit_triggers_on_flood`

### Hinweis zur Stabilität des Tests
Der Test startet den Status-Server mit einem temporären, selbstsignierten TLS-Zertifikat im Temp-Ordner. Dadurch ist der Test unabhängig von lokalen CA-Dateien in `~/.phantom`.

### Befehle
```bash
cargo test -p phantom-node --test mempool_dos_unripe_microtx_a7
```
